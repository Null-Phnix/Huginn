## What This Is

v1.1-alpha fixes the foundations. Before adding killer features (structured extraction, MCP server, Python SDK), the core needed to be solid. Five problems were identified and fixed:

1. Pages weren't loading properly — just dumb `asyncio.sleep`
2. Crawls hit the same content twice with no dedup
3. Transient errors (timeouts, 502s) killed scrapes with no retry
4. Crawls ignored robots.txt — bad etiquette and legal risk
5. Infinite-scroll pages (Twitter, Reddit, product feeds) returned partial content

Each fix was built test-first: write failing tests, implement, verify the full suite stays green, commit.

## Task 1: Smart Wait Strategies

**Problem:** `scraper.py` did `await asyncio.sleep(wait_for / 1000)` — a hardcoded sleep. No way to wait for a specific element or for network activity to settle. Slow and unreliable.

**Solution:** The `WaitStrategy` enum and `parse_wait_for()` function give the system four strategies:

| Strategy | Input | Behavior |
|---|---|---|
| `TIMEOUT` | `3000` (int) | Sleep for N ms (backward compatible) |
| `SELECTOR` | `"div.content"` (CSS string) | Wait for element to appear in DOM |
| `NETWORK_IDLE` | `"networkidle"` / `"network-idle"` / `"network_idle"` | Wait for network to settle |
| `DOM_CONTENT_LOADED` | `"domcontentloaded"` | Fast — just wait for DOM ready |

`BrowserManager.smart_wait(page, strategy, value, timeout_ms)` executes the strategy on a Playwright page. Selector and networkIdle strategies have timeouts (default 10s) and fail gracefully with a warning instead of crashing.

**Files changed:**
- `huginn/browser.py` — `WaitStrategy` enum, `parse_wait_for()`, `smart_wait()` method
- `huginn/scraper.py` — replaced `asyncio.sleep` with `parse_wait_for` + `smart_wait`
- `huginn/models.py` — `wait_for` field now accepts `Optional[Union[int, str]]`
- `huginn/__init__.py` — exported `WaitStrategy` and `parse_wait_for`

**Tests:** 11 (enum values, parsing int/float/string/null/selectors, integration with smart_wait)

**API usage:**
```json
// Old way (still works)
{ "url": "https://example.com", "wait_for": 3000 }

// New ways
{ "url": "https://example.com", "wait_for": "div.main-content" }
{ "url": "https://example.com", "wait_for": "networkidle" }
{ "url": "https://example.com", "wait_for": "domcontentloaded" }
```

## Task 2: Content Hashing for Duplicate Detection

**Problem:** When crawling a site, the crawler would visit the same content multiple times (e.g., paginated lists that link back, canonical vs non-canonical URLs, near-identical pages). This wastes requests and pollutes results.

**Solution:** `content_hash()` and `is_duplicate()` in `crawler.py`.

`content_hash(text)` normalizes whitespace and case, then SHA-256 hashes the result, truncated to 16 characters. This means pages with minor whitespace differences or case variations hash to the same value.

`Crawler` now has `skip_duplicates: bool = True` by default and an internal `_seen_hashes: set` that tracks content hashes across the crawl. Before adding a page to results, it checks `is_duplicate()` — if the hash is already seen, the page is skipped.

**Files changed:**
- `huginn/crawler.py` — `content_hash()`, `is_duplicate()`, `skip_duplicates` param, `_seen_hashes` set
- `huginn/models.py` — `CrawlRequest` doesn't need changes (dedup defaults to on)

**Tests:** 5 (normalization, collision detection, empty input, dedup enable/disable)

**Behavior change:** Crawls are now deduplicated by default. Set `skip_duplicates=False` to get the old behavior.

## Task 3: Retry with Exponential Backoff

**Problem:** A single timeout or 502 error would fail the entire scrape. No retry logic existed. In the real web, transient errors are common — CDN hiccups, rate limits, temporary outages.

**Solution:** `classify_error()` + retry loop with exponential backoff.

`classify_error(error)` inspects the exception and returns `(error_type, http_status_code)`:
- `asyncio.TimeoutError` → `("timeout", 408)`
- `ConnectionRefusedError` / `ConnectionError` / `ConnectionResetError` / `OSError` → `("connection", 502)`
- Everything else → `("unknown", 500)`

`Scraper.scrape()` now wraps the entire page load + extraction in a retry loop:
- Default: 2 retries (3 total attempts)
- Exponential backoff: 1s, 2s, 4s between retries
- Client errors (4xx) are NOT retried — they're the server saying "you're wrong"
- Rate limits (429) and server errors (5xx) ARE retried
- `max_retries` is configurable per-request via the API (`0` to `5`)

**Files changed:**
- `huginn/scraper.py` — `classify_error()`, `DEFAULT_MAX_RETRIES`, `RETRY_BACKOFFS`, retry loop in `scrape()`
- `huginn/models.py` — `max_retries: int = Field(2, ge=0, le=5)` on `ScrapeRequest` and `ScrapeOptions`
- `huginn/api.py` — passes `max_retries` through to scraper

**Tests:** 15 (classify_error for 5 error types, retry constants, async retry integration, max_retries validation)

**API usage:**
```json
// Default: 2 retries
{ "url": "https://example.com" }

// Aggressive: 5 retries
{ "url": "https://flaky-site.com", "max_retries": 5 }

// No retries (fail fast)
{ "url": "https://example.com", "max_retries": 0 }
```

## Task 4: Robots.txt Parsing

**Problem:** The crawler would follow every link it found, including paths that site owners explicitly disallowed in robots.txt. This is both rude and potentially a legal issue.

**Solution:** `RobotsChecker` class in `crawler.py`.

How it works:
1. Before a crawl begins, `RobotsChecker.fetch_rules(url)` fetches `{origin}/robots.txt` via `httpx.AsyncClient`
2. Parses `User-agent: *` rules (the wildcards that apply to all bots)
3. For each URL the crawler wants to visit, `is_allowed(url)` checks the path against all Disallow and Allow rules
4. Uses longest-match priority: if a path matches both an Allow and Disallow rule, the longer pattern wins (per RFC 9309)
5. If robots.txt can't be fetched (404, network error), defaults to **allow** — we don't block the entire site just because robots.txt is missing

The `Crawler` has `ignore_robots: bool = False` by default (robots.txt checks are ON). Set `ignore_robots=True` on the crawl request to skip checks.

**Files changed:**
- `huginn/crawler.py` — `RobotsChecker` class (fetch_rules, is_allowed, _parse methods)
- `huginn/models.py` — `ignore_robots: bool = Field(False)` on `CrawlRequest`

**Tests:** 12 (robots parsing, allow/deny precedence, missing robots.txt, CrawlRequest field)

**API usage:**
```json
// Default: respects robots.txt
{ "url": "https://example.com" }

// Skip robots.txt (you know what you're doing)
{ "url": "https://example.com", "ignore_robots": true }
```

**Robots.txt example that HUGINN handles correctly:**
```
User-agent: *
Disallow: /admin
Disallow: /private/
Allow: /private/public-page
```
- `/admin` → blocked
- `/private/secret` → blocked
- `/private/public-page` → allowed (longer Allow pattern wins)

## Task 5: Infinite Scroll Handling

**Problem:** Many modern sites (Twitter/X, Reddit, Instagram, product feeds) load content dynamically as you scroll. HUGINN would only capture what's visible in the initial viewport — missing the majority of the content.

**Solution:** `ScrollConfig` + `BrowserManager.auto_scroll()`.

`ScrollConfig` is a Pydantic model:

| Field | Default | Description |
|---|---|---|
| `max_scrolls` | 10 | Maximum scroll iterations (min 1) |
| `delay_ms` | 500 | Milliseconds to wait between scrolls for content to load |
| `scroll_to_bottom` | True | Whether to scroll back to top after finishing |

`auto_scroll(page, config)` works by:
1. Reading `document.body.scrollHeight`
2. Scrolling to the bottom via `window.scrollTo(0, document.body.scrollHeight)`
3. Waiting `delay_ms` for new content to load
4. Checking if `scrollHeight` changed since the last scroll
5. If height stabilized (same as last iteration) → stop early, content is fully loaded
6. If `max_scrolls` reached → stop, we've done enough
7. If `scroll_to_bottom=True` → scroll back to top

Returns the number of scrolls performed (useful for debugging/monitoring).

**Files changed:**
- `huginn/browser.py` — `ScrollConfig` class, `auto_scroll()` method on `BrowserManager`
- `huginn/models.py` — `scroll: bool = Field(False)` on `ScrapeRequest` and `ScrapeOptions`
- `huginn/scraper.py` — `scroll` param wired through, calls `auto_scroll` when enabled
- `huginn/api.py` — passes `scroll` param through scrape endpoint
- `huginn/__init__.py` — exported `ScrollConfig`

**Tests:** 10 (ScrollConfig defaults/validation, auto_scroll count/stops-on-no-growth/max-limit/scroll-to-top/no-scroll-to-top/default-config)

**API usage:**
```json
// Enable auto-scroll for infinite-scroll pages
{
  "url": "https://twitter.com/search?q=AI",
  "scroll": true
}

// Custom scroll config via actions (advanced)
{
  "url": "https://example.com/feed",
  "scroll": true,
  "actions": [
    { "type": "scroll", "direction": "down", "amount": 1000 }
  ]
}
```

The `scroll: true` flag on ScrapeRequest activates `auto_scroll()` with defaults (10 scrolls, 500ms delay, scroll back to top). For more control, you can still use manual scroll actions in the `actions` array.

## Architecture Impact

All changes are **additive** — no existing behavior was broken. The API contract is backward compatible:

- `wait_for: 3000` still works (TIMEOUT strategy)
- `ScrapeRequest` without `max_retries` defaults to 2 retries
- `ScrapeRequest` without `scroll` defaults to no scrolling
- `CrawlRequest` without `ignore_robots` defaults to respecting robots.txt
- Crawl dedup is ON by default but can be disabled

The `BrowserManager` grew two new methods:
- `smart_wait()` — replaces dumb sleep
- `auto_scroll()` — handles infinite scroll

The `Crawler` grew two new capabilities:
- `_seen_hashes` — content dedup tracking
- `_robots_checker` — robots.txt compliance
